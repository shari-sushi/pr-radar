# pr-radar

複数リポジトリにまたがる open PR / draft PR を、1画面で見るための個人用ダッシュボード。

ビルドなし・依存なしの HTML 1枚。GitHub API を直接叩く。

PR 一覧は REST（リポジトリごとに1リクエスト）。カードに出すコメント数だけは、
REST の一覧レスポンスに入っていない（単体 GET にしかない）ため GraphQL で取る。
PR ごとに単体 GET すると N+1 になるが、GraphQL なら全リポジトリぶんが1リクエストで済む。

## 使い方

```sh
git clone git@github.com:<owner>/pr-radar.git
cd pr-radar
./run.sh
```

`run.sh` が出す URL（既定は `http://127.0.0.1:49787/`）を開いて、**設定** から次の2つを入れる。

- **アクセストークン** — 下記参照
- **Author** — 自分以外で追いたい人の GitHub ID（自分は `/user` から自動で入る）

盤面は open / closed のタブで分かれる。タブは PR の状態の1軸だけで、「誰の PR か」はレーンが持つ。

closed は**タブを開いたときに初めて取りに行く**ので、普段の更新は今までと同じ速さのまま。この endpoint には期間で絞る手段が無い（`state` / `sort` / `direction` / `per_page` / `page` だけ）ので、リポジトリごとに30件ずつ取り、取った分は全部出す。足りなければ末尾の「もっと見る」で次のページを継ぎ足す。自動更新では取り直さない（送ったページが毎回巻き戻るため）。更新ボタンを押したときだけ1ページ目から取り直す。

closed には件数（comment / review / inline）を出さない。済んだものに「前回から増えた」の意味が薄いため。代わりに `merged` / `closed` のチップが付く。

登録した author は自分も含めてチェックボックスで並ぶ。扱いは3通り。

| author | 行き先 |
| --- | --- |
| 一覧にあり、チェック済み | 左の列（`Ready for Review` / `Draft`） |
| 一覧にあり、チェックを外した | 右の列の `un-select author` |
| 一覧に無い | 右の列の `unlisted author` |

チェックを外すのは「この人はいま見ない」という意思表示だが、「居ない」とは別なので、盤面から落とさず右の列へ回す。一覧に載せていない人は意思表示が無いだけなので `unlisted author` に残る。`Requested from me` だけはチェックと無関係で、常に自分宛のものを拾う。

closed タブだけは扱いが違い、チェックを外した人の PR は出さない。閉じたものに「レビューに出すかどうか」の軸は無く、残るのは「誰の PR か」だけなので、`Closed` と `unlisted author` の2本に分かれる。

盤面は2列。左が自分が動くかもしれない PR、右が眺めるだけの列。出すレーンは盤面の上の絞り込み行から選ぶ。外したレーンは要素ごと消え、片方の列が空になれば1列に寄る。

自動更新する曜日も選べる（既定は毎日）。1つも選ばないと自動更新しなくなるので、そのときは設定欄に赤字で出る。

自動更新を止める時間帯も設定できる。`19:00 〜 09:00` のように日をまたぐ指定もできる。止まるのはタイマーだけで、更新ボタンと `r` はいつでも効く。開始と終了の片方だけ、あるいは同じ時刻を入れた場合は止めない（設定欄に赤字で出る）。

盤面の幅は3つから選ぶ（`w-narrow` / `default` / `almost-full`）。数字では持たない —— 詰めたい幅は画面ごとに違うので、決めた形から選ぶほうが早い。**レーンが1列に寄っているとき / 2列とも出ているときで別々に覚える。**同じ幅でも、1列のときは広すぎ、2列のときは狭すぎ、ということが起きるため。

対象リポジトリと自動更新間隔も設定から変えられる。自動更新は秒で入れるが、`60*30` のように四則演算でも書ける（`+ - * / ( )` だけの小さなパーサで読む。`eval` は使っていない）。入力の下に何秒になったかが出る。

同じ author のチェックは、設定の中と盤面の上（ヘッダーの水平線の直下）の2か所に出る。どちらを押しても同じものが動く。帯は1行に並び、人数が増えて幅からはみ出たときだけ横スクロールになる。

設定の「追う人」と「出すリポジトリ」のトグルは、並んでいるものを出す / 出さないだけで、一覧そのものは足せない。足す先は基本設定の Author 欄・リポジトリ欄なので、並びの末尾に「＋ 追加する」を置いてある。押すとその欄が開き、そこまでスクロールして入力欄にフォーカスが入る。トグルが1つも無いときも出るので、まだ何も入れていない状態からでも辿れる。

author のチェック・目のボタン・リポジトリの絞り込みは、押した時点で反映され、そのまま保存される（`pr-radar:view`）。レーンのトグル・盤面の幅・タブも同じ扱い。

盤面の上の who / repo のチップは、hover すると対応するカードが光る（カードの左にレーンの色が出る）。数が増えてくると「このリポジトリのぶんはどれか」を目で拾うのが辛くなるため。設定の引き出しの中の同じチップからも効く。

repo・who・lane・自動更新の曜日・盤面の幅は、どれも同じトグル（`toggleBtn()` と CSS の `.tgl`）で出している。「押されている / いない」の色は `.tgl` が1か所で持ち、4つの状態（on / off / on+hover / off+hover）を全部書き出してある。使う側は形と字だけを足す ——

| | 形 | off の見せ方 |
| --- | --- | --- |
| repo・曜日・幅 | 角ばった箱（`.tgl` の既定） | 取り消し線 |
| who | 丸い錠剤 | 破線の枠 ＋ 薄く |
| lane | 角丸 | 薄く |

色を共通にして形で見分けるのは、「押されている」がどの色なのかを画面の場所ごとに読み替えずに済ませるため。`toggleBtn()` に `kind` を渡さなければ `.tgl` の既定の形で出る。

絞り込み行の「待ち」「closed」「merged」と目のボタンは `.tgl` とは別の CSS だが、**向きは揃えてある —— 押されている＝盤面に出している。**外したものは薄い字＋取り消し線に落ちて、`.repo` と同じ見え方になる。以前は逆向き（押されている＝盤面から外している）で、外したものが一番濃く出ていた。並んだトグルごとに「濃い＝どっち」を読み替えることになるので、向きを揃えた。

### PR に付ける印

各カードの右下の目のボタンで `scope-in` / `scope-out` を切り替える。既定は `scope-in`（そのまま表示）で、押すと `scope-out`＝伏せた扱いになり、その行は薄くなる。

絞り込み行（`待ち` の右）にある目のボタンは、伏せた PR を盤面に残すかどうかの切り替え。押していない＝伏せた PR を盤面から消している。この状態も押した時点で保存され、次に開いたときも続く。

値は `index.html` の `LABELS` に enum として置いてあり、増やすときはここに足す。

```js
const LABELS = { IN: "scope-in", OUT: "scope-out" };
```

フッターの日付 `08/19 - 3時間前` は、左が作成日、右が最終更新からの経過。ホバーすると作成日時と最終更新が `260819_14:07` の形（`yymmdd_hh:mm`）で出る。`title` 属性ではなく自前の吹き出しで、出るまでは 0.1 秒固定（メモの吹き出しの遅延設定とは連動しない）。

フッターの `comment: 1 review: 1 inline: 5` はひとつのボタン。押すとその時点の3つの数を覚え、以後は増減を `+2` `-1` のかたちで数字の脇に出す。以後は覚えた数と違うあいだだけ色が濃くなる。同じあいだは押す前と同じ見た目で、枠も付かないので並びはずれない。

覚えがない PR は「まだ何も見ていない」＝ 0 件として比べるので、コメントが1つでも付いていれば濃く出る。合計ではなく3つ別々に持つ。合計だと、コメントが1つ消えてレビューが1つ増えたような入れ替わりを見落とすため。

PR名の下にはブランチ名が2本出る。PR名と同じく左寄せで、`<このPR> → <merge先>` の順。矢印が入る向きを表す。どちらを押してもその名前がクリップボードへコピーされる（`git switch` に貼るため）。merge 先は前回のキャッシュには入っていないので、更新するまでは矢印なしでこの PR のブランチ名だけが出る。

いちばん左のペンのボタンでメモを書ける。画面中央に textarea が出て、見出しにはその PR のカードがそのまま入る。外側を押すか Esc で保存して閉じる（保存ボタンは無い）。見出しのカードの下には「待ち」のチェックも並ぶので、書きながら切り替えられる。空にして閉じるとキーごと消える。メモがある PR はボタンの地色が変わり、ボタンにホバーすると中身がそのまま出る（既定は0.9秒で出て、離すとすぐ消える。出るまでの時間は設定のスライダーで変えられる（1秒までは0.1秒刻み、そこから5秒までは0.5秒刻み）。`title` 属性ではなく自前の吹き出しなので、長い本文でも勝手に落ちない）。

その右に「待ち」のチェックボックスがある。絞り込み行の「待ち」ボタンを外すと、印の付いた PR が盤面から消える（自分の手を離れているものを畳んで、動かすべきものだけを残すため）。伏せる（目のボタン）とは別の軸なので、互いに干渉しない。こちらは覚えるだけで、レーンにも絞り込みにも見た目にも影響しない。scope とは別の軸なので、キーも分けてある。

| | 保存場所 | 形 |
| --- | --- | --- |
| 表示するか | `localStorage` の `pr-radar:labels` | `{ "owner/repo#123": "scope-out" }` |
| 待ち | `localStorage` の `pr-radar:waiting` | `{ "owner/repo#123": true }` |
| メモ | `localStorage` の `pr-radar:memos` | `{ "owner/repo#123": "CI 待ち" }` |
| 最後に見た件数 | `localStorage` の `pr-radar:seen` | `{ "owner/repo#123": [1, 1, 5] }` |
| 前回の取得結果 | `localStorage` の `pr-radar:cache` | 盤面が使う項目だけに削ったもの。開いた瞬間に出すためだけで、正はいつでも GitHub 側 |
| 画面の状態（目・待ち・closed / merged・author のチェック・リポジトリとレーンの絞り込み・盤面の幅・開いていたタブ・吹き出しの遅延） | `localStorage` の `pr-radar:view` | `{ "showOut": false, "showWaiting": true, "showMerged": true, "showUnmerged": true, "memoDelay": 0.9, "widthOne": "default", "widthTwo": "almost-full", "off": ["octocat"], "hidden": ["example-org/repo-b"], "laneOff": ["draft"], "tab": "open" }` |

持つのは伏せたものだけ。既定の `scope-in` まで書くと、閉じた PR のぶんが増える一方で消す当てがないため、既定に戻したらキーごと消している。トークンと違って秘密ではないので暗号化はしていない。設定は `localStorage` に保存されるので、次回からは開くだけ。トークンは端末の外に出ない（送信先は `https://api.github.com` のみ）。

### 選んでコピーする

`Ready for Review` と `Draft` の見出しの右にコピーのボタンがある。押すと**選択モード**に入り、各カードにチェックが出る。選んだぶんをまとめて1回でコピーする。

| ボタン | 出るもの |
| --- | --- |
| 重なった紙のアイコン | 一覧だけ。1件2行で、1行目が `- repo #123 タイトル`、2行目が全角スペース下げの URL |
| 書類のアイコン | `REVIEW_TEMPLATE`（`@channel` から始まるレビュー依頼の下書き）の末尾に、上の一覧を足したもの |

文面のほうは `Ready for Review` の見出しにだけ出る。出す前の PR にレビュー依頼の文面は要らないため。

選択は**レーンをまたぐ**。`Ready for Review` と `Draft` は別のレーンだが、貼る先は同じ1つの投稿なので、レーンごとに区切ると2回コピーして2回貼ることになる。見出しに出る「コピー N件」も、そのレーンの数ではなくまとまり全体の数。

「全選択 / 全解除」は1つのトグル。選択0なら全選択、1件以上なら全解除になる。

選んでいるあいだは自動更新を待たせる（捨てずに一時停止する）。閉じたときに1回だけ走らせるので、見に戻った瞬間がいちばん新しい。絞り込みで盤面から落ちた行は数にも本文にも入らない —— 見えていないものを黙ってコピーしない。

### 歯車 — この PR を動かす

各カードの右下、目の右にある歯車で、その PR を GitHub 側で動かせる。画面中央に modal が出る。

| 操作 | 中身 |
| --- | --- |
| `draft` / `not draft` | 2択のスイッチ。塗られている側がいまの状態で、もう一方を押すとそちらへ動く（GraphQL の `convertPullRequestToDraft` / `markPullRequestReadyForReview`） |
| `update branch` | base を取り込む（`PUT /repos/{owner}/{repo}/pulls/{n}/update-branch`）。ボタンに遅れているコミット数が出る |
| この1件をコピー | 一覧と同じ書式で1件だけ。PR を変えないので、状態が読めなくても押せる |

押せないときはボタンを灰色にするだけで済ませず、理由をホバーに出す（`閉じた PR` / `コンフリクトがある` / `base に追いついている` など）。

draft を切り替えたら、GitHub 側の一覧が追いつくのを待たずに**先に盤面を動かす**。待ってからにすると、直したのにレーンが変わらない時間ができるため。裏で 0 / 3 / 10 秒と取り直して、本物が追いついた時点で当てていたぶんを外す。

modal を閉じても処理は止めない。相手は GitHub で、こちらが見ているかどうかとは関係なく進む。閉じたあとの進捗と結果は画面の下の行が引き受ける。

**この2つは書き込みなので、トークンに `Pull requests: Read and write` が要る。**読み取り専用のトークンでは 403 になる（歯車以外は Read-only で動く）。

### なぜ `run.sh` を使うのか

`python3 -m http.server` を直接叩かず、スクリプト経由で起動する。3点を固定するため。

- **各自が1つのポートを pr-radar 専用にする。** `localStorage` は「scheme + host + **port**」単位で分離される。あとから同じポートで別プロジェクトを配信すると、そのページから pr-radar の設定が読める。ポートは端末ごとに選べる（下の「ポート」）が、選んだ1つを pr-radar 専用にすることは変わらない
- **`--bind 127.0.0.1` で自分の端末に閉じる。** `python3 -m http.server` の既定は全インターフェースへの bind なので、同じ Wi-Fi にいる誰でもこの画面を開けてしまう
- **`--directory public` で `public/` だけを配信する。** 配信されるものを列挙できる形に閉じ込めるため。リポジトリの直下を配信すると、`README.md` も `run.sh` も `.git/` も、あとから置いたメモも、全部 HTTP で読める

```text
pr-radar/
├── public/          ← ここだけが配信される
│   ├── index.html
│   ├── shari-porp-b.png
│   └── key.js       ← run.sh が生成。git 管理外
├── run.sh
├── port.local       ← 配信ポート。任意・git 管理外
├── README.md
└── .gitignore
```

`public/index.html` をブラウザで直接開いても表示はされるが、上の分離が効かないので `./run.sh` を使う。

### ポート

既定は `49787`。変えるなら `port.local` を置く。

```text
port=50123
```

`PR_RADAR_PORT=50123 ./run.sh` でも指定できる。両方あれば `port.local` が勝つ。

選べるのは **49152〜65535**（dynamic / private range）だけ。範囲外を書くと起動せずに止まる。`3000` や `8080` を選ぶと、あとからそこで別プロジェクトを配信したときに pr-radar の `localStorage` を渡すことになるため。

`--bind 127.0.0.1` と `--directory public` は固定で、選べない。

#### ポートを変えると設定は引き継がれない

`localStorage` はポート単位で分かれるので、ポートを変えた瞬間に**別オリジン**になる。トークン・設定・絞り込み・メモ・待ちの印・既読の基準が全部空で立ち上がる。アプリ側から前のオリジンのデータは読めない。

消えたわけではなく元のポート側に残っているので、`port.local` を戻せば戻る。`run.sh` は前回のポートを `last=` に覚えていて、変わっていたら配信を始める前に警告する（端末から叩いたときは続けるか聞く）。

これは**アカウントを分けて使う**ためにも使える。仕事用と個人用を別ポートで立てれば、トークンも設定もメモも混ざらない。

## トークン

Fine-grained personal access token を推奨。手順は設定画面の「アクセストークン」の脇にある <kbd>?</kbd> にも同じものが出る。


| 項目 | 値 |
| --- | --- |
| Resource owner | 対象リポジトリを持つ organization |
| Repository access | Only select repositories → 対象の3つ |
| Repository permissions | **Pull requests: Read-only** のみ（歯車を使うなら Read and write） |

`Metadata: Read-only` は自動で付く（外せない）。`Contents` は不要 —— ファイルの中身には触らないため。

盤面を見るだけなら `Read-only` で足りる。カードの歯車から draft を出し入れする / update branch を押すには `Read and write` が要る（「歯車 — この PR を動かす」）。要らないなら `Read-only` のままでよく、歯車を押したときだけ 403 になる。

organization をリソースオーナーにする場合、org 側で fine-grained PAT が許可されている必要があり、設定によってはオーナーの承認待ちになる。

classic token を使う場合はプライベートリポジトリに `repo` スコープが必要だが、これは書き込み権限も含むので推奨しない。SAML SSO 必須の org では発行後に Configure SSO で認可する。

## トークンの保管

`localStorage` に平文で置くと、同一オリジンの JavaScript から誰でも読める。初回起動時に `run.sh` が `public/key.js`（32バイトの乱数）を作り、トークンはこの鍵で AES-GCM 暗号化してから `pr-radar:token` に保存する。他の設定は `pr-radar:config` に平文のまま。

| | 保存場所 | git |
| --- | --- | --- |
| 鍵 | `public/key.js`（この端末のみ） | 管理外（`.gitignore`） |
| 暗号文 | `localStorage` | — |

守れるのは「**あとから同じポートで別のものを配信され、その localStorage を読まれる**」ケース。ポートは1プロセスしか掴めないので、そのとき pr-radar は動いておらず、攻撃者ページから `public/key.js` は取得できない。暗号文だけ持っていても復号できない。

守れないのは、**pr-radar を配信している最中に同一オリジンでコードを実行された**ケース。そのときは `public/key.js` も一緒に読まれる。だから `run.sh` の `--directory public` 固定（同一オリジンに他のものを置かない）とセットで意味を持つ。

鍵を作り直すとトークンは復号できなくなるので、入れ直しになる。それだけで済むので、**画面共有・配信・スクリーンショットなどで `public/key.js` の中身を晒したら作り直すこと。**

```sh
rm public/key.js && ./run.sh
```

`public/key.js` が無い、または `file://` で開いた場合は暗号化できないため、トークンを保存せずタブを閉じるまでの一時利用になる（設定画面に赤字で表示される）。

## 表示のしくみ

各リポジトリの `GET /repos/{owner}/{repo}/pulls?state=open` を叩き、クライアント側で5つのレーンに振り分ける。上から順に評価し、最初に当たったレーンに入る。

| レーン | 列 | 条件 |
| --- | --- | --- |
| `Requested from me`（依頼） | 左 | `requested_reviewers` に自分が入っている |
| `Ready for Review`（待ち） | 左 | 作者がチェック済みの author・draft でない |
| `Draft`（下書） | 左 | 作者がチェック済みの author・draft |
| `un-select author` | 右 | 作者は一覧にあるが、チェックを外している |
| `unlisted author` | 右 | 残り全部（一覧に載せていない人） |

`Requested from me` を先に判定するので、相方が自分にレビューを振った PR は `Ready for Review` ではなく `Requested from me` に出る。

closed タブは `Closed`（左）と `unlisted author`（右）の2本だけ。閉じた PR にレビュー依頼の軸は無いので見ない。

7日以上更新のない PR には停滞バッジ、14日以上なら赤で表示する。

## 既知の制約

- レビューを提出すると `requested_reviewers` から自分が外れるため、往復中の PR は `Requested from me` から落ちて、作者で決まるレーンに移る。拾いたい場合は `GET /pulls/{n}/reviews` を追加で叩く必要がある（必要な権限は Pull requests: Read のまま）
- チーム宛のレビュー依頼（`requested_teams`）は見ていない。個人指名のみ
- open は各リポジトリ 100件までしか取らない。ページングなし（closed は「もっと見る」で30件ずつ継ぎ足せる）
- CI の状態やレビューの承認状況は一覧レスポンスに含まれないので表示していない

## キーボード

| キー | 動作 |
| --- | --- |
| `r` | 更新 |
| `s` | 設定の開閉 |
| `Esc` | 開いているもの（操作 → メモ → 設定 → 選択モード）を1つ閉じる |

メモ・歯車の modal を開いているあいだと、選択モードのあいだは `r` / `s` を拾わない。`r` は更新なので、選んだ途中が消えるため。`Esc` だけは入力欄の中からも効く。
